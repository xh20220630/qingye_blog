去年此时画了一份聚灵阵初稿，解决的是「灵气进来」的问题。今年夏天家中进了两次贼（一次是野猫，一次是推销的），遂意识到：聚灵之后，还要护山。这篇推演护山大阵，即一个洞府的安全体系。

先说总纲：护山大阵的核心不是墙，是「分层」。任何一道防线被破，后面还有一道。做系统安全的道友看到这里已经笑了，对，纵深防御，山里山外，一个理。

## 三层防线

```python
def 入阵(来客, 令牌):
    # 第一层：山门，验明正身
    if not 验令牌(令牌):
        return 迷踪阵(来客)  # 让他在雾里转圈，自行下山

    # 第二层：院墙，划分权限
    区域 = 查权限(来客)
    if 区域 == "丹房":
        return 婉拒("丹房重地，丹童亦不得入")

    # 第三层：居室，最小授权
    if not 预约(来客, 今日):
        return 茶叙("客厅吃茶，院中勿扰")

    return 引入(区域)
```

第一层山门，对外，解决「你是谁」，即鉴权。令牌过期不候，没有「这次先放进来」的说法，安全上的例外一旦开口，就再也关不上。第二层院墙，对内，解决「你能去哪」，即权限分区。丹房、库房、居室各自独立，破了一处不至于满盘皆输。第三层居室，解决「此刻是否合适」，即最小授权加时间窗。今日未预约，纵然是多年老友，也请客厅吃茶。

> 兵法讲「善守者藏于九地之下」，系统安全讲「assume breach」，假设早晚会被攻破。两家的共同结论：别指望一道墙，指望墙后面还有墙。

## 给阵留一扇后门

推演中最纠结的一笔：要不要留后门。正道说法是不要，阵法森严，岂可自留破绽。但我想起两件事。一是某年小区消防演习，消防通道被杂物堵死的那栋楼，评分最低。二是公司某次事故，所有人在门外看着告警干着急，因为应急通道的钥匙在唯一休假的同事手里。

所以后门要留，但要按后门的规矩留：

- 后门平时封印，封条上写开启条件，比如「主阵失灵且洞主在其中」。
- 钥匙分两半，一半在道侣处，一半在山下老友处，单一半无用。
- 每年启封演练一次，免得真到用时，发现锁已经锈死。
- 开启即触发告警，后门从来不是秘密通道，是应急通道。

这就是「灾备」与「逃逸通道」的区别。前者是设计出来的，后者是事故逼出来的。价格相差十倍，效果也相差十倍。

## 反入侵推演

推演了几种入侵剧本。野猫型：无恶意，纯路过，迷踪阵送走即可，不必惊动内层。推销型：有目的但无技术，山门令牌即可拦下，重点在不为赠品开门。同道切磋型：懂行，有令牌的可能，此时第二层分区是关键，就算对方进了山门，也只在客厅范围活动，丹房与库房纹丝不动。

最值得记的是第四型：内贼。权限是自己人滥用的，防不了，只能审。所以阵中留日志，谁何时入何区，皆有记录。日志平时无人看，出事时是唯一的证人。

## 结语

阵图推演完毕，尚未施工，原因与去年相同：预算审批流程较长。道侣审阅后批注：野猫那次，阵先不论，厨房窗能不能先换个锁。深以为然。护山大阵，从最便宜的那道防线修起。

另有一事忘了写入阵图：推演的第三天，我在图纸角落给野猫留了个猫洞，注曰「非武装目标通道」。道侣见了说，这不算防御漏洞吗。我说算，但一座连猫都要防的山，住着也没什么意思。安全与生活之间，阵法要留一点人情味的冗余，这个冗余不计入指标。
